# Dependency & Package Management Standards (R)

## Core Principles
1. **Standard `DESCRIPTION` & `NAMESPACE`**: For R packages, declare metadata, minimum R version (`Depends: R (>= 4.2.0)`), runtime `Imports:`, and optional/test `Suggests:` cleanly in `DESCRIPTION` with `NAMESPACE` generated by `roxygen2` (`ProjectFacts.language_version_constraint`).
2. **Reproducible Environments (`renv.lock` — Analysis App vs. CRAN Package Distinction)**:
   - **Data Pipelines / Shiny Apps / Analytical Services**: Commit `renv.lock` (`renv::snapshot()`) for reproducible CRAN/Bioconductor environments (`ProjectFacts.lockfiles_found`).
   - **Published CRAN / Bioconductor Packages**: Omitting `renv.lock` (relying on `DESCRIPTION` version floors) is standard R package convention and must **NOT** be penalized.
3. **Clean `Imports` vs `Suggests` & Minimal `Depends`**: Avoid listing non-R packages in `Depends:` (pollutes user search path); place test/doc tools (`testthat`, `knitr`, `rmarkdown`, `covr`) strictly in `Suggests:` with minimum version floors (`ProjectFacts.unpinned_dependencies`).
4. **Vulnerability & Archive Auditing**: Verify packages are actively maintained on CRAN/Posit Package Manager (not archived/removed) and scan container/system libraries with Trivy.

## Evaluation Thresholds
- **`PASS`**: Supported R `>= 4.1`, clean `DESCRIPTION` (`Imports`/`Suggests`) or `renv.lock` for apps/pipelines, and zero `Depends:` namespace pollution.
- **`WARN`**: Missing minimum version floors on core dependencies or missing `renv.lock` on Shiny/analysis apps.
- **`FAIL`**: Undocumented implicit `install.packages()` calls inside source scripts, broken `NAMESPACE`, or archived/vulnerable dependencies.
